# 現行 Logic Horse（LLMプロンプト連鎖）の診断と新系統との違い

## 現行スタイル（共有いただいた手順）

```text
① DBから対象レース関連の約10年分を抽出
② AIプロンプトで「レースの特徴」を文章化
③ 出走馬をDB紐付け → AI専用出走馬表（JSON）
④ プロンプト + JSON で本予想
⑤ 当日情報（馬場・前レース・最新オッズ・馬体重）を渡して最終予想
```

評価は RPM-10（変更しない）。最近は **的中率・回収率とも大幅悪化**。

---

## なぜこのスタイルは精度が崩れやすいか

LLMプロンプト連鎖は「説明は上手い」が、競馬の長期エッジには弱い。悪化の典型因は次。

| 要因 | 何が起きるか | 症状 |
| --- | --- | --- |
| **非決定性** | 同じJSONでも日によって印がブレる | 再現不能・検証不能 |
| **人気追随** | ⑤で最新オッズを渡すと、AIが市場の人気をなぞる | 的中は出ても回収が死ぬ／逆に人気崩れで両方死ぬ |
| **10年一括要約の情報損失** | ②で長い履歴を「特徴」に圧縮し、数値の差が消える | 条件適性が曖昧な本命 |
| **複勝発想の残り** | 「残しそう」な馬を強く書く | 勝ちきり条件とズレる |
| **プロンプトドリフト** | 週ごとの指示追加でルールが肥大 | 先月まで効いていた手順が壊れる |
| **リーク／時点の曖昧さ** | 学習でも運用でも「いつ時点のオッズ・体重か」が混ざる | バックテストと実戦が一致しない |
| **フィードバック欠如** | 外れた理由が「AIの気分」になり、係数を直せない | 悪化に気づけても修正不能 |

最近の同時悪化（的中↓かつ回収↓）は、だいたい:

1. オッズ・当日情報に引っ張られて軸がブレる  
2. 要約②が弱く、コース適性の差が出ない  
3. 厳選せず全レース（or 多レース）に同じプロンプトを当てている  

のいずれか（複合が多い）。

---

## 現行で「残してよい」ものと「止めた方がよい」もの

| 残す | 止める／弱める |
| --- | --- |
| DBの10年分 **数値抽出そのもの** | ②の「特徴をAIに要約させる」を予想の本線にすること |
| ③の構造化JSON（馬ごと過去走） | ④⑤を最終印の唯一の決定者にすること |
| 当日の馬場・体重の **数値ログ** | 最新オッズをAIに渡して「最終判断」させること |
| RPM-10での公開評価 | プロンプトを毎週増やすこと |

オッズは「買ってよいか」のゲート用。**印を決める入力にしない**（新系統の方針と同じ）。

---

## 新系統（`next/`）への切り替え方

予想の仕方のプランは維持。変えるのは **誰が数値を見て印を出すか**。

```text
現行 LLM型
  DB抽出 → AI要約 → AI印 → AI最終（オッズ込み）

新系統
  DB抽出 → 勝ちきり条件照合（数値）→ race_pattern
        → 印・T1〜T7 → odds_floor/EVでケン
        （LLMは使わないか、説明文の生成だけ）
```

| 段 | 現行 | 新系統 |
| --- | --- | --- |
| レース特徴 | ② AI文章 | `course_key` + 場×距離×枠の勝率表 |
| 馬評価 | ④ AI総合印象 | `win_score`（勝ちきり照合） |
| 厳選 | プロンプト任せ | Solid/Chaos でケン |
| 当日オッズ | ⑤ 最終予想に投入 | 床ゲートのみ（印は変えない） |
| 再現性 | 低い | 同じDBなら同じ印 |

並行運用:

- 当面 **実戦・X・RPM-10 = 現行のまま**
- 新系統は同じ開催をペーパーで回し、的中・回収・見送りを比較
- 新系統が安定して勝ってから主軸を移す

---

## 直近の悪化への応急（現行をまだ使う場合）

現行を急に止めない前提での止血:

1. **⑤から「最新オッズで印を変えろ」を禁止**（オッズは参考表示のみ）  
2. **買うレースを減らす**（混戦・新馬・情報不足は見送り）  
3. プロンプトを増やさず、**固定プロンプト1本**に戻す  
4. 週次で「AIが◎にした馬の単勝人気分布」を見る → 1〜3番人気偏りが強すぎたら人気追随  

根本治療は新系統の数値パイプライン側。
