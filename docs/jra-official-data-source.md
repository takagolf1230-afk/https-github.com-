# データソース方針: JRA公式（JRA-VAN Data Lab / JV-Data）

採用データ: **JRA公式データを購入して使う**（JRA-VAN Data Lab の JV-Data）。  
JRDB独自指数・スクレイピングを主データにはしない。不足分はJV-Dataから自前集計する。

想定アクセス: Cursor側で `jv_data.db`（または同等の展開DB）を `--db` 指定。  
このクラウド環境にはDBが無い前提。

仕様の正本: [JRA-VAN Data Lab JV-Data仕様](https://jra-van.jp/dlb/ddata.html) / JV-Data PDF。

---

## 1. 必須A〜D と JVレコードの対応

| 必要塊 | 用途 | JV側の主な元データ | 典型テーブル/レコード |
| --- | --- | --- | --- |
| **A 過去走** | 馬評価 | 馬毎レース情報・成績 | `SE`（馬毎レース）→ UMA_RACE 系 |
| **B 今走出走** | 相対比較・適性 | レース詳細・出馬表 | `RA`（レース詳細）、出馬表区分の SE |
| **C 結果・払戻** | 的中・回収検証 | 確定成績・払戻 | SE 確定、`HR`（払戻）→ HARAI 系 |
| **D 今走オッズ** | 床ケン・EV | 速報/時系列オッズ | `O1`〜`O6`（単複枠〜三連単） |

補足マスタ（加点・人の補正）:

| 用途 | JV側 |
| --- | --- |
| 競走馬属性・脚質傾向 | 競走馬マスタ |
| 騎手・調教師成績 | 騎手マスタ / 調教師マスタ |
| 血統 | 繁殖馬マスタ等 |
| 参考指数（主特徴にしない） | データマイニング予想（使うなら補助のみ） |

## 2. レコード種別の実務メモ

JV-Dataでよく使う種別（仕様書のID）:

| ID | 内容 | パイプラインでの使い方 |
| --- | --- | --- |
| RA | レース詳細（距離・芝ダ・天候馬場・コンディション等） | 必須B、コース条件 |
| SE | 馬毎レース（枠・斤量・着順・タイム・通過・着差等） | 必須A/B/C |
| HR | 払戻 | 必須C |
| O1 | 単勝・複勝・枠連オッズ | 必須D（単複） |
| O2 | 馬連 | 必須D |
| O3 | ワイド | 必須D |
| O4 | 馬単 | 必須D |
| O5 | 三連複 | 必須D |
| O6 | 三連単 | 必須D |

SE / RA の **データ区分** に注意（木曜出走馬名表、金土出馬表、速報成績、月曜確定など）。  
学習・バックテストは **月曜確定（成績）** を正とし、予測時点シミュレーションでは **出馬表時点＋購入時点オッズ** だけを使う。

## 3. 必須項目チェック（JVで揃うか）

### A 過去走（SE中心）

- [x] 馬ID・レースキー・日付で時系列追跡
- [x] 着順・走破タイム・着差
- [x] 上がり3F・コーナー通過順（提供開始以降）
- [x] 距離・芝ダ・競馬場・馬場・斤量・馬体重
- [x] 騎手・調教師

→ **馬評価は公式データだけで足りる。** スピード指数は自前計算（標準化タイム等）。

### B 今走出走（RA + 出馬表SE）

- [x] 枠番・馬番・斤量・当日騎手
- [x] コース条件・頭数・クラス
- [x] 取消・除外の扱い（データ区分・フラグで除外）

### C 検証（SE確定 + HR）

- [x] 確定着順
- [x] 券種別払戻

### D 購入ゲート（O1〜O6）

- [x] 単勝〜三連単オッズ
- [x] 速報オッズ / 時系列オッズ（締切前スナップショットを保存できるとよい）

→ 回収率・オッズケンには **O系の保存が必須**。成績DBだけだと回収ゲートが作れない。

---

## 4. 公式データ運用ルール

1. **主データはJVのみ**（ネット独自指数に依存しない）  
2. 能力指数が欲しければ JVのタイム・通過・斤量・馬場から **自前で作る**  
3. データマイニング予想を使う場合も **印の主材料にしない**（人気近似になりやすい）  
4. 学習特徴に **確定オッズを入れない**。オッズは O1〜O6 の購入時点スナップでゲート  
5. 実集計は `--db /path/to/jv_data.db`（パスは環境依存）  
6. 新馬・情報不足は厳選で落とす（公式でも過去走が薄い）

---

## 5. パイプライン（公式データ版）

```text
jv_data.db
  RA + SE(出馬表)     → 今走出走セット
  SE(過去確定)        → 馬スコア (win/place/dark)
  上位差/和           → race_pattern (Solid/AxisEdge/Mid/Chaos)
  印 → T1〜T7
  O1〜O6 スナップ     → odds_floor / EV → 購入 or ケン
  SE確定 + HR         → 的中率・回収率集計
```

---

## 6. 次アクション（DB接続時）

1. `jv_data.db` の実テーブル名を列挙し、上表と1対1でマッピング表を埋める  
2. 過去走クエリ（当該レースより前のSEのみ）を1本化する  
3. O1〜O6の「どの時刻のスナップを買う判断に使うか」を決める（例: 発走15分前）  
4. 必須A+B+Cだけで機械印バックテスト → 次にDで回収ゲート
