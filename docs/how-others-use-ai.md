# 他の予想家のAI活用（現行①〜⑤との対比）

成績が残っている側の「AI」は、だいたい **機械学習（LightGBM等）** で、チャットAI（ChatGPT等）ではない。  
チャットAIを使う場合も、**印の決定者にはしない**。

---

## 1. 本体: 数値モデルが印を出す

典型（PC-KEIBA、Qiita、うまろう等）:

```text
過去走を特徴量にする
  → LightGBM Ranker（同レース内の順位）
  → スコア上位を印・軸にする
  → オッズは最後に EV = 予測確率 × 実オッズ
  → 閾値未満は買わない
```

共通ルール:

- レース内の相対順位を学習する（「この馬は強い」絶対評価だけにしない）
- **オッズ・人気は学習特徴に入れない**（入れると市場の写しになり、回収が払戻率付近に落ちる）
- 評価は的中率だけでなく回収率（ROI）
- 時系列で未来を検証する（ランダム分割しない）

出典の型: [PC-KEIBA LambdaRank](https://pc-keiba.com/wp/lambdarank/)、[うまろう 回収率140%](https://note.com/umaro_ai/n/n35fa601babd4)、[Zenn Echo Chamber](https://zenn.dev/yurelu/articles/396a329522aa22)

---

## 2. チャットAIの使い方（印の外）

使っている人の役割は次に限られる。

| 使い方 | やってよい | やってはいけない |
| --- | --- | --- |
| 開発相談 | 特徴量の案、バグ、検証設計を議論 | その会話結果をそのまま買い目にする |
| 文章化 | 決まった印の解説をX用に書く | 解説の過程で印を変える |
| コード | SQL・集計スクリプトの下書き | プロンプトを毎週足してルールを増やす |
| 当日メモ | 馬場・前走の事実を箇条書き | 最新オッズを渡して最終印を出させる |

Zennの事例では、Gemini と26ラウンド議論して **MLの設計を直した**（オッズ特徴を外して ROI 0.91→1.66）。会話AIはコーチで、予想エンジンではない。

---

## 3. 現行 Logic Horse との違い

| | 現行（①〜⑤） | 成績が出ている使い方 |
| --- | --- | --- |
| 誰が印を出すか | チャットAI | 数値モデル |
| 10年データ | ②で文章要約 | 特徴量のまま残す |
| 当日オッズ | ⑤で最終予想に投入 | 購入ゲートだけ |
| 再現 | 同じ入力でもブレる | 同じDBなら同じ印 |
| 直し方 | プロンプト追加 | 特徴量と検証指標を直す |

現行の⑤（オッズ込み最終予想）は、他の人が「やってはいけない」と書いている Echo Chamber に近い。

---

## 4. このプロジェクトでの置き方

```text
印・券種・ケン  → next/ の数値（勝ちきり照合 → 将来 LightGBM）
チャットAI      → 解説文・開発相談のみ（印は変えない）
RPM-10 / X      → 現行の公開軸のまま（並行期間）
```

LightGBM は P2 以降。今の `win_score` ルールが実DBで動いてから載せる。  
チャットAIを予想の最終段に戻さない。
