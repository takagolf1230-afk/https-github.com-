# 勝ちきり条件の抽出と出走馬照合（新系統専用）

## 結論

**やる。** 現行が複勝特化なら、新系統の差別化はまさにここ。

- 現行: 3着以内に残る力（place）
- 新系統: **1着になれる条件が揃っているか（win）** を先に見る

予想の全体プラン（race_pattern → 印 → T1〜T7 → オッズケン）は変更しない。  
その中の **`win_score` / ◎判定の中身** を「勝ちきり条件マッチ」にする。

```text
JV公式DB
  ├─ 過去の「1着サンプル」から勝ちきり条件を集計
  ├─ 今走のレース条件・競馬場条件をベクトル化
  └─ 出走各馬のプロフィールと照合 → win_fit / win_score
        ↓
  （既存プラン）race_pattern → 印 → 券種 → odds/EVゲート
```

---

## 1. なぜ複勝特化と分けるか

| | 複勝向き | 勝ちきり向き |
| --- | --- | --- |
| 問い | 崩れにくいか | **この条件で1着を取れるか** |
| 効くもの | 安定感・位置取り・騎手複勝 | コース適性・枠×脚質・展開の勝ち筋 |
| 印 | △まで広げやすい | ◎の質が勝負 |
| 失敗 | 当てても薄い | 条件不一致の「強そうな馬」を◎にしがち |

現行の place ロジックは触らない。新系統だけ win 条件を別テーブルで持つ。

---

## 2. 抽出する「条件」の次元（JRA公式で取れる）

### 2.1 レース・競馬場条件（今走のキー）

JV `RA` から今走をキー化する:

| 次元 | 例 | 勝ちきりへの意味 |
| --- | --- | --- |
| 競馬場 | 東京/中山/阪神… | 回り・直線・坂の型 |
| 芝ダ | 芝/ダ | 全く別競技 |
| 距離帯 | 1200 / 1400–1600 / 1800–2000 / 2200+ | 適距離 |
| コース詳細 | 内外・右左（場とセット） | 小回り vs 直線長 |
| 馬場 | 良〜不 | パワー/キレの向き |
| クラス | 未勝利〜G1 | 相手関係（勝ちきり難度） |
| 頭数 | 少/中/多 | 展開ノイズ |
| 枠・馬番 | 内〜外 | 脚質とセットで勝ち筋 |

このキーを `course_key` と呼ぶ（例: `阪神|芝|外|2400|良`）。

### 2.2 馬側プロフィール（過去SEから）

各馬について、**1着になった走**と**凡走**を分けて集計:

| プロフィール | 中身 |
| --- | --- |
| 同 course_key の勝率・連対率 | 再現性の芯（CourseFlag的） |
| 同競馬場×芝ダの勝率 | 場適性 |
| 距離帯の勝率 | 距離適性 |
| 脚質（逃先差追）× 勝ちパターン | どういう立ち回りで勝ったか |
| 枠帯（内中外）での勝率 | 枠適性 |
| 良/稍/重/不での勝率 | 馬場適性 |
| 「勝ちきり力」 | 1着率 vs 複勝率の差（複勝ばかりなら勝ちきり弱い） |

複勝特化システムが見る「残る力」と違い、ここでは **1着イベントだけを厚く数える**。

## 3. 照合の仕方（出走馬 × 今走条件）

今走の `course_key` と各馬プロフィールを突き合わせる。

```text
for 各出走馬:
  win_fit = 0
  + score(同 course_key の過去1着・複勝)
  + score(同場×芝ダ)
  + score(距離帯一致)
  + score(想定脚質 × 今走の勝ちやすい枠帯)  # 場×距離の枠別勝率表と照合
  + score(馬場一致)
  - penalty(同条件で大敗が多い)
  - penalty(複勝はするが勝率が極端に低い)   # 勝ちきれない馬
  win_score = normalize(win_fit) をレース内相対化
```

レース内で `win_score` を並べ:

- 1位が大きく抜け → ◎候補・axis High
- 上位が横並び → Mid/Chaos（ケン寄り）
- 1位は抜けているが place 上位と食い違う → 軸は win、ヒモは place 系（後述）

サンプル不足（同条件0〜1走）の馬は加点を抑え、血統・近走タイムは補助に留める（公式データ優先）。

## 4. 全体プランへのはめ方（変更しない部分）

| 段 | 内容 | 勝ちきり照合の役割 |
| --- | --- | --- |
| L1 スコア | win / place / dark | **win を本ドキュメントの照合で作る** |
| L2 パターン | Solid / AxisEdge / Mid / Chaos | win_score の差・和で分類 |
| L3 印 | ◎○▲△☆ | ◎○▲は win 順、△は place、☆は dark |
| L4 券種 | T1〜T7 | そのまま |
| L5 ゲート | odds_floor / EV | そのまま |

印の役割分担（現行複勝との差分）:

```text
◎○▲  ← win_score（勝ちきり条件マッチ）
△     ← place_score（残る力・現行に近い発想を新系統内でも別計算可）
☆     ← dark + 条件一致の穴（例: 同コース勝ちがあるが人気薄）
```

これで「複勝は拾えるが勝ちきれない馬」を◎にしにくくなる。

---

## 5. 事前に作っておく集計表（オフライン）

バックテスト前に JV 確定SEから作る辞書:

1. **場×芝ダ×距離帯×枠帯の勝率表**（コースが勝ちやすい枠・脚質）  
2. **場×芝ダ×距離帯×脚質の勝率表**  
3. **馬ごとの course_key 別 1着/出走**  
4. **馬ごとの「勝率÷複勝率」**（勝ちきり指数）

件数閾値: セルの N が小さいと採用しない（Team.D型のサンプル制約）。

---

## 7. 注意

- 同条件実績が少ない馬（特に若駒）は win_fit を盛りすぎない → 厳選でケンしやすい  
- 「複勝率高い＝◎」にしない（それが現行との差）  
- 枠の有利不利は脚質なしで単独使いしない  
- 勝ちきり条件が揃っていても odds_floor 未満ならケン（回収）
