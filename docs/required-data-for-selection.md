# レース厳選・予想に必要なデータ一覧（的中＋回収）

目的: **レースを厳選**しつつ、的中率と回収率の両方を上げるために、過去走DB／オッズから何が必要かを優先度付きで固定する。

方針の両立:

- 的中: 軸が読めるレースだけ買う
- 回収: 的中しても薄いオッズはケン。期待値（予測確率×実オッズ）が立つ点だけ残す
- オッズは **馬評価の主特徴にしない**（人気追随になる）。**選別・購入ゲート**に使う

```text
必須データで馬スコア
  → レース構造スコア（厳選）
  → 印・軸・テンプレ
  → 実オッズで床ゲート＋期待値ゲート
  → 購入 or ケン
```

---

## 1. 結論: 最低限これがあれば厳選できる

| 優先 | データ塊 | 何に使うか |
| --- | --- | --- |
| **必須A** | 過去走成績（馬ごと・時系列） | 能力評価 `win_score` / `place_score` |
| **必須B** | 今走のレース条件・出走表 | 相対比較、展開、適性 |
| **必須C** | 払戻・着順（過去） | バックテスト（的中率・回収率） |
| **必須D** | 単勝〜三連単の実オッズ（今走） | オッズ床ケン、期待値、回収ゲート |
| 強く推奨 | 通過順・上がり・ペース | 展開・脚質・穴根拠 |
| 強く推奨 | 騎手・調教師成績 | 人の補正 |
| あると良い | 血統・調教・馬体重推移 | 精度の底上げ |
| 後回し | 時系列オッズ（秒単位）・合成オッズ高度化 | 上級の回収最適化 |

あなたの「過去走DBで馬評価できる」は **必須A** に相当。回収まで上げるなら **必須D（オッズ）** と **必須C（検証用払戻）** が追加で要る。

---

## 2. 必須A: 過去走成績（馬評価の芯）

1頭×過去走ごとの行が必要。予測対象レースの結果は **絶対に含めない**（`shift(1)`）。

| 項目 | 例 | 用途 |
| --- | --- | --- |
| 馬ID / レースID / 日付 | | 時系列結合 |
| 着順 | 1〜18 | 過去成績集計（当該走は除外） |
| 走破タイム | 秒 | 標準化タイム・指数 |
| 着差 | 秒/馬身 | 能力差 |
| 上がり3F | 秒 | 末脚・脚質 |
| 通過順位（最低코너通過） | 1角〜4角 | 脚質・展開適性 |
| 距離 / 芝ダ / 競馬場 / 内外 | | 条件別成績 |
| 馬場状態 | 良〜不 | 適性 |
| 斤量 | kg | 負担補正 |
| 馬体重・増減 | kg | 状態 |
| 騎手ID / 調教師ID | | 人の成績結合 |
| クラス・レース名コード | 未勝利〜G1 | 相手関係の正規化 |
| 単勝人気・単勝オッズ（過去走） | | 「当時の評価」参照用（今走予測の主特徴にはしない運用も可） |

これから作る集計（馬評価）:

- 直近3〜5走の平均/最良スピード指数（または標準化タイム）
- 同距離帯・同競馬場・同芝ダの複勝率
- 脚質ラベル（逃/先/差/追）と先行率
- 休み明け間隔、距離延長/短縮フラグ

---

## 3. 必須B: 今走の出走表・レース条件

| 項目 | 用途 |
| --- | --- |
| レースID、発走日時 | キー |
| 競馬場、コース（芝ダ、距離、内外、回り） | 適性・コースバイアス |
| クラス、頭数、年齢条件 | 厳選（情報不足レース除外） |
| 枠番・馬番 | 枠バイアス |
| 斤量、馬体重（当日） | 補正 |
| 騎手・調教師（当日） | 人の補正 |
| 天候・馬場（当日または直前） | 展開・適性 |
| 出走取消・除外フラグ | 組合せ再計算 |

レース厳選に効く派生:

- 出走頭数（多すぎるとノイズ）
- 新馬/情報が薄い馬の割合
- 当該コースの過去「人気信頼度」（必須Cから集計）

---

## 4. 必須C: 結果・払戻（検証用）

回収率を上げる設計には、予測と同じ粒度の正解が要る。

| 項目 | 用途 |
| --- | --- |
| 確定着順 | 的中判定 |
| 単勝〜三連単の払戻金 | 回収率・標準偏差 |
| （任意）確定単勝オッズ | 人気ベースライン比較 |

バックテストで必ず出すKPI:

- 見送り率
- Passレースの的中率（券種別）
- **回収率とその標準偏差**
- オッズ床ケンで落とした点の「もし買っていたら」比較

---

## 5. 必須D: 今走オッズ（回収ゲート）

的中だけなら後回しにできるが、**回収を上げるなら必須**。

| 項目 | 用途 |
| --- | --- |
| 単勝オッズ（全頭） | 軸の薄さ・期待値の分母 |
| 複勝オッズ | 参考 |
| ワイド / 馬連 / 馬単 / 三連複 / 三連単 | 券種別 `odds_floor` と期待値 |
| 取得時刻（締切前のどの時点か） | リーク防止。学習に確定オッズを使うな |

使い方（回収向け）:

```text
1) モデルは過去走だけで勝率・連対率を出す（オッズ非依存）
2) 実オッズと掛けて期待値 EV = p_hat × odds を出す
3) EV が閾値未満、または odds < odds_floor → ケン
4) 残った点だけ買う
```

これで「当てる力」と「割安だけ買う力」を分離できる。慶應論文・回収率113%系AIも、大枠はこの分離。

---

## 6. 強く推奨: 展開・穴根拠用

神戸新聞杯型（軸堅・下位荒れ）で三連単の☆を残すために必要。

| 項目 | 用途 |
| --- | --- |
| 過去の通過順・平均ペース | 逃げ候補・先行密度 |
| コース×枠のバイアス統計 | 内外有利 |
| 当日の前レース傾向 | 差し有利など |
| 血統（父・母父）の距離/芝ダ成績 | 初距離・条件替わり |

`dark_score` の材料になる。これがないと☆は付けられず、軸堅レースは低配当ケンか薄いワイドだけになりやすい。

---

## 7. あると良い / 後回し

| データ | 優先 | 理由 |
| --- | --- | --- |
| 調教・ウッドタイム | あると良い | 状態面。取得・正規化コスト高 |
| パドック・気配 | 後回し | 属人的・再現しにくい |
| 秒単位オッズ時系列 | 後回し | 回収の上級最適化 |
| 合成オッズ高度化 | 後回し | 既存方針どおり |
| 地方・障害 | 対象外でも可 | 中央平坦から始める |

---

## 8. レース厳選に使うスコアと、必要なデータの対応

| 厳選スコア | 必要なデータ | 回収との関係 |
| --- | --- | --- |
| `axis_confidence` | 必須A+B（能力差） | Highでも低オッズなら本線ケン |
| `field_chaos` | A+通過順+人気/オッズ順位ズレ | Highならワイド薄→三連単候補 |
| `info_density` | クラス・出走歴の長さ | 薄いレースは的中も回収も不利→ケン |
| `odds_floor_pass` | 必須D | 床下はケン |
| `ev_pass` | 予測確率×必須D | 回収の本命ゲート |

厳選の最終判定例:

```text
Pass 条件:
  axis_confidence >= Mid
  AND info_density 十分
  AND （本線オッズが床上 OR 昇格券種が床上かつ EV 十分な点がある）

それ以外 → ケン
```

## 9. DBに揃っているかチェックリスト

過去走DB（あなた所持）を点検するときの質問:

1. 馬IDで過去走を時系列に辿れるか
2. タイム・着差・上がり・通過があるか
3. 競馬場×距離×芝ダが揃っているか
4. 着順・払戻でバックテストできるか
5. **今走の券種別オッズを、購入時点相当で取れるか**（回収に必須）
6. 取消・除外を扱えるか

1〜4がYesなら馬評価と的中寄り厳選は可能。  
5がNoだと、的中は測れても **回収最適化とオッズケンができない**。

## 10. 実装時の取り方（jv_data / JRA-VAN系を想定）

`--db` で触る想定の論理テーブル（名前は環境に合わせて読み替え）:

| 論理 | 中身 |
| --- | --- |
| races | レース条件 |
| entries | 出走表（馬・騎手・枠・斤量） |
| results | 着順・タイム・通過・上がり |
| payoff | 券種別払戻 |
| odds_snapshot | 購入判断用オッズ |
| horses / jockeys / trainers / sires | マスタと集計用 |

最低クエリ単位:

1. 対象レースの entries + races  
2. 各馬の過去N走 results（当該レースより前）  
3. 集計してスコア → 印 → テンプレ  
4. odds_snapshot で床/EVゲート  
5. 事後に payoff で的中・回収を集計  

---

## 11. データ優先で進める順番

1. **必須A+B+C** で機械印と T1〜T6、見送り率・的中率を出す  
2. **必須D** を繋ぎ、`odds_floor`＋簡易EVで回収率を測る  
3. 通過順・バイアスで `dark_score` を足し、T3（軸堅・下位荒れ）の回収を伸ばす  
4. 調教・血統は効果が頭打ちしてから  

合成オッズは、上記で回収のボトルネックが「組合せ評価」だと分かってからでよい。
